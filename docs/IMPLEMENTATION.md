# 實作與驗證範圍

更新日期：2026-09-26。此文件描述目前 `voxel-castle-game` 原始碼及附帶證據，不將規格中的要求視為已完成結果。

玩法依據為《MEGA IDLE 重製執行 Prompt：蒼嵐堡體素世界與完整遊戲整合》的第 2～14 節及數值附錄；視覺依據為「蒼嵐堡基準 v1」。這是本次建立的獨立本機遊戲實作，沒有宣稱已遷移其他專案、帳號或原版存檔。

## 程式與資產

城堡視覺種子預設為字串 `94721`，地圖生成版本為 `2`。`WorldMap` 目前使用固定地形種子，`worldSeed` 只影響城堡與表面外觀，尚未支援任意地形種子。玩法使用獨立的亂數狀態，鏡頭、剖視、日照和場景切換不產生玩法獎勵。不能以原始觀賞器的方塊數或幾何指紋代表目前遊戲。

## 可使用的系統

- 主循環：三類招募與保底、心願單、五隊編制、六職業與前後排、十八技能、十區主線與四難度、首領機制、自動續戰、敗退休整、掉落與離線結算。
- 養成：訓練、突破、升星、鎖定、遣散、重置、置換、碎片合成；七裝備部位、十階六星、強化、六套裝、十三配方、四類寶石、鑲嵌、融合、洗練與素材轉換。
- 城堡：十座獨立建築、未建地基和三階外觀、訪客活動與招募、訪客遠征、名冊委託、商店、圖書館、榮譽、共鳴及昇華傳統。
- 長期系統：主線、日週任務、成就、圖鑑、簽到、寶箱、活動；秘境、兩種競技、公會／世界首領、元素塔、迷宮、無盡深淵、神器與傳說徽章。

主狩獵使用逐步結算的實際戰鬥。秘境、競技、首領挑戰等擴展模式使用戰力／隊伍資料進行數值結算，結果顯示在面板與紀錄；其場景地標是功能入口，尚非各自完整的可視戰鬥舞台或可行走室內。

## 效能：實測數字與工具

`node tools/perf-probe.cjs` 會在桌機／手機／小手機三種尺寸各量一次，並用 CDP 的 CPU 降速模擬手機處理器；加上 `--headed` 才會用真的 GPU（不加時是軟體渲染，frame 時間沒有參考價值）。2026-09-26 實測（本機桌機 GPU、Chrome、狩獵中＋戰鬥視角）：

| 視角（地圖放大兩倍後） | draw call | 三角形 | 方塊 | JS heap |
|---|---|---|---|---|
| 城堡 | 89 | 2.77M | 289k | 91 MB |
| 世界地圖／戰鬥 | 165 | 3.42M | 289k | 91 MB |

（CPU 降速 ×6 時每幀 JS 2.7～4.5ms；地形 209,466 塊 ＋ 城堡 74,783 塊）

- 世界地圖視角（看得到整塊大陸）是 draw call 最多的角度：165。地形原本每 64 格切一塊，地圖放大兩倍後會變成 450，所以分塊邊長跟著改成 128。整個世界仍是實例化繪製（1 個 geometry、1 個 texture）。
- pixel ratio 上限 1.25（寬度 <650）／1.5（其餘），陰影貼圖 1024（手機）／2048，且 `shadowMap.autoUpdate=false`——只有場景真的變動才重畫陰影。
- **這張表不能拿來宣稱手機 GPU 沒問題**：量到的是桌機 GPU 與軟體渲染兩種極端。真機的填充率、發熱與續航仍需在實機驗收。

設定裡的「畫質」可以在執行中調整（`world.setQuality('auto'|'high'|'low')`，偏好存在 `canglan-preferences-v1`）：

| 畫質 | pixel ratio | 陰影 | 量到的 draw call |
|---|---|---|---|
| 低（省電） | 1 | 關閉 | 23 |
| 自動 | 1.25（手機）／1.5（桌機） | 1024（手機）／1536 | 23 |
| 高 | 2 | 2048 | 23 |

切換會即時重建 shadow map 並重編材質；瀏覽器測試會斷言低畫質真的關陰影、高畫質把陰影拉到 2048。像素量差距很大（390×844 的 DPR1 → DPR2 是 4 倍像素），但這台桌機 GPU 快到量不出差異——**省下的是手機的填充率與電**。

### 回到前景的補算不再凍住畫面

背景待機或畫面卡住之後要補算流失的遊戲時間。舊版把整段塞在同一帧：CPU 降速 ×6（手機級）時補 60 秒 264ms、補 5 分鐘 1029ms、補 1 小時 8.3 秒，畫面會整個凍住。現在每一帧最多補 1.5 秒（`CATCHUP_PER_FRAME`），剩下的留給後面幾帧分次還；固定步長模擬本身沒有改變，分批等價性由 `tests/core.test.cjs` 既有測試守住。超過 90 秒的停頓仍走 `C.offline()` 的閉式結算。

## 觸控與 App 殼

手機上會干擾遊戲的瀏覽器預設手勢全部關掉：`viewport` 鎖 `user-scalable=no`，`html` 給 `touch-action:manipulation`（沒有雙擊縮放）與 `overscroll-behavior:none`（沒有下拉重新整理與橡皮筋），`body` 不可選字、關掉 iOS 長按選單，3D 畫布與浮動控制列用 `touch-action:none`（拖曳與雙指縮放完全由遊戲處理），面板與橫向分頁列保留 `pan-x pan-y` 才滑得動。

`manifest.webmanifest` 讓手機可以「加到主畫面」，之後以 `display:standalone` 全螢幕執行，連網址列與上一頁手勢都沒有。App 圖示（192／512／apple-touch-180）由 `node tools/make-icons.cjs` 產生——純 Node 自寫 PNG 編碼器，不引入任何美術素材或套件。

## 介面主題

介面與圖示是暖色色盤：羊皮紙（`--paper:#f3ddab`／`--panel:#ffedc8`）、木框、森林綠主要動作（`--green:#45673a`）、金色強調。換色是機械化的：`node tools/warm-theme.cjs` 用「舊色 → 新色」對照表置換 `style.css` 的 183 個顏色引用（`--check` 可列出沒對照到的顏色），圖示色盤在 `js/icons.js` 的 `P`。世界畫面左上角標題改成奶油字＋暖色陰影，因為 3D 場景底色會變，深字會糊掉。

## 保存與時間

存檔格式 `version: 1`，本機儲存鍵為 `canglan-save-v1`；聲音與鏡頭偏好使用 `canglan-preferences-v1`。匯入前檢查資源、等級、裝備歸屬、占用、亂數和擴展資料。生成版本 `1` 的舊存檔升至 `2` 時會清除舊地圖行走狀態，在下一個遊戲步長重建；資源、英雄、目標與玩法 RNG 保留。無法辨識的格式仍被拒絕。

戰鬥倍率只套用戰鬥時間；回復、休整、訪客與遠征使用實際時間。日週期採台北日期。離線主狩獵按目前目標估算收益，扣除剩餘休整、分段處理增益到期並限制 12 小時；不假造離線首通與推關。這是單機瀏覽器存檔，沒有伺服器權威時間或跨裝置同步。

## 開放地圖

`castle`／`facilities`／`zones` 三個場景群組永遠可見，`setView('castle'|'battle'|'map')` 只改變相機（近景城堡／飛往當前狩獵區／拉遠看大陸），不再切換場景。因此 `getStats()` 的方塊數在任何視角下都相同；`worldBlocks` 是不含演員的靜態方塊數，用於斷言「沒有換場景」。

角色步行跟隨動畫影格推進（`walkDt`，上限 0.4 秒），戰鬥與休整跟隨遊戲時鐘；兩者在正常幀率下同步，在軟體渲染的 headless 環境下步行會落後，因此相關測試等待的是狀態而不是秒數。

## 場域：位置與戰鬥同步

隊伍與怪物的位置是**遊戲資料**，不是畫面動畫。`hunting.field` 保存 `party[{id,x,z,pi,path}]` 與 `foe{x,z,homeX,homeZ,aggro,path}`，全部用世界 XZ 座標；`game-core.js` 的 `fieldStep()` 與 `battleStep()` 在 `tick` 的同一個 0.1 秒子步裡一起推進（`while(h.accumulator>=.1){fieldStep(s,.1);battleStep(s,.1);}`），並且都乘上戰鬥速度。畫面端 `world.js` 只把 `state.hunting.field` 畫出來（位置做了收斂平滑，但權威值永遠是資料）。

- **接觸才開打**：`fieldContact(s)` 算出每個人到怪物的距離；超出 `heroRange` 的英雄不攻擊也不施放技能，怪物超出 `foeRange` 也不攻擊。走位與傷害因此不可能脫鉤。
- **隊形與追擊**：`settleParty()` 每步把隊伍座標推開到 `FIELD.gap`（2.6 格）以上，只往 `stepOk()` 允許的方向推，所以不會被推進牆、水或岩石裡；怪物則維持硬性排除半徑 `heroRange*.62`。成員路線走完卻仍在 `heroRange` 之外時，會以怪物當前位置（就近吸附到可站格）為目標重新找路，不會停在集結線上旁觀。
- **中途重新找路**：世界段重算路線一律走 `WorldMap.smoothPath()`（RDP 簡化＋逐格驗證），所以走一半改路也跟原本的大路一樣平順。
- **尋路**：世界長途使用 `WorldMap.findPath()` 與逐步 `validStep()` 檢查，競技場內仍由 `GameData.zones[i].field.walkable()` 與局部 A* 判定 `props` 障礙。隊伍路線為「庭院 → 城門 → 大陸道路 → 閘門 → 集結線 → 近戰位」；怪物追擊每 0.5 秒重新尋路。換怪後已用盡路線的隊伍會重新接近怪物。
- **仇恨**：怪物在 `aggro`（16 格）內鎖定最近的存活英雄，追到自己的 `foeRange` 就停；超出 `leash`（34 格）或無人存活就回崗位。最後一步會被夾住避免踏進英雄身體，每步結束再做一次隊形分離，保證雙方不穿模。
- **退場**：戰敗只退到該區閘門（`fieldReturn(s,true)`），休整後 `autoContinue` 重新出兵時從原地續走，所以反覆挑戰同一區不會一直重付長途行軍；玩家主動召回才走完整條回家的路（`fieldReturn(s,false)`），走完才釋放場域。
- **存檔**：`hunting.field` 會存進存檔並通過 `validateSave`，且推進是決定性的（相同輸入產生相同場域）。

大陸由 `WorldMap` 的格網產生，`buildTerrain()` 逐格繪出分層地形、水面和群系裝飾；遠區平坦同材質格可合併成 4 × 4 方塊。海岸基準半徑 504（471～558），十區中心距城堡約 260–474，最小間距 160。地形繪製分三層 LOD（±175 用 2 格、±400 用 4 格、其餘 8 格），分塊邊長 128。隊伍從城門走到第 1～10 區約 14～30 秒。城堡外圈是八邊形（四邊 x ±92、z ±78，四角切 42；台地 6、護城河 16、特區 20 都是同一個形狀等距外推），內圈維持矩形 x ±57、z −50…+36；`castleDist()` 是唯一的形狀來源，導航的牆格、護城河與畫面方塊都讀它。道路與橋面由同一份導航資料決定。`node tools/world-audit.cjs` 驗收十區連通、城門唯一出口、坡度和地形規模。

世界路線由 `WorldMap.routeTo()`／`routeBetween()` 提供；`GameData.ring` 保留相容呼叫介面，十區位置與旋轉角度皆由 `WorldMap.zones` 取得。近戰位與局部障礙由 `GameData.zones[i].field` 提供。

測試程式是可重跑的驗證方式，交付是否通過須以當次執行結果為準。瀏覽器測試使用測試存檔和加速接口檢查後期模式；這些接口只在 `?test` 啟用，測試資料不代表正常進度。軟體 WebGL 下的繪製呼叫和資源界限不等同具名顯示卡的穩定幀率。

## 目前未達成的規格驗收

1. **免費首次昇華及長期平衡。** 現有七天模擬報告的 `reachedFirstAscension` 為 `false`，缺少三座核心建築 Lv10。策略曾在狩獵占用期間嘗試養成，且未妥善處理後期敗退；此結果說明該策略未通過，不能推導全部免費路線不可行。各隊伍策略的等時比較亦未完成。
2. **逐項內容追溯。** 現有覆蓋表主要按內容家族計數，尚未為每一筆建立完整 `sourceRule / assetId / sceneId / stateBinding / 互動測試 / 視覺測試` 對照。稀有度、套裝和神器等圖示使用家族共用造型。
3. **完整戰鬥演出與音訊。** 十八技能有數值效果與戰報，但場景攻擊／命中主要以生命變化觸發，未提供每項技能逐段專屬動作、投射物和首領特效。音訊目前是通用操作提示及簡單合成和弦，未完成各武器、工坊與環境的音色家族。
4. **完整替代操作與可讀性驗收。** 有標準鍵盤焦點和導覽替代入口，尚未有手把映射及完整鏡頭方向按鈕。高對比、粒子量、鏡頭震動、200% 文字放大與標籤避碰，尚未全面驗證。
5. **更多表現與效能證據。** 有日夜光照、剖視與三段式畫質（自動／高／低）。尚無季節／天氣系統、可視距離 LOD 策略、完整屋頂隱藏控制。桌面 GPU 與軟體渲染已量過，**實體手機的填充率、發熱與續航仍未驗收**；WebGL 故障恢復也需進一步驗收。

因此本次交付可作為可玩開發版與後續整合基礎，尚不符合原規格第 17 節的「完整完成」判準。

## 未明定數值的補定

未有原文精確數字的實作補定記錄於 `GameData.supplements`、`GameExtensions.supplements` 及相應程式。例如分解金幣、通用素材池機率、訪客出現／活動間隔、部分挑戰係數、委託與公會成長。防禦姿態採 50% 直接減傷，敗退使用推算的敵方參考戰力。這些值是本次重建補定，不能當成原版資料。

自動穿裝逐步選擇不降低完整角色／隊伍戰力的替換，沒有窮舉七個部位的所有套裝組合。任何後續數值調整應補記原值、新值、測試條件與理由，並重跑受影響的規則測試。
