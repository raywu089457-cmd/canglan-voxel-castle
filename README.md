# 蒼嵐堡・獵人公會

以大型體素城堡為樞紐的單人放置狩獵 RPG。十個副本區域以城堡為圓心排成一圈，**全部和城堡同處在一張連續地圖上**；戰鬥不再切換場景，隊伍會從城門走出去、沿著環狀道路走到該區，在原本的地圖上開打。城牆、塔樓、城門、庭院和地形使用實例化幾何生成；招募、編隊、狩獵、掉落、建築與存檔已接到同一份遊戲狀態。

這是可執行的開發版。完整規格仍有未完成的視覺、操作及長期驗收項目，詳見 [實作與驗證範圍](docs/IMPLEMENTATION.md)。

## 啟動

**線上版（GitHub Pages）**：<https://raywu089457-cmd.github.io/canglan-voxel-castle/>
不用安裝任何東西，用瀏覽器打開就能玩（手機也可以）。存檔存在該網址自己的瀏覽器空間，跟下面的本機服務是**兩份不同的存檔**；要搬進度請用設定裡的匯出／匯入。

### 本機

需要 Node.js，以及可用 WebGL 的桌面瀏覽器。此專案附帶所有執行素材，不需要 `npm install`、帳號或外部 API。

在本目錄開啟終端機：

```powershell
npm start
```

也可執行 `node server.cjs`。看到啟動訊息後，瀏覽 [http://127.0.0.1:4173](http://127.0.0.1:4173)。在終端機按 `Ctrl+C` 停止伺服器。

預設僅在本機開放。若 4173 已被占用，可先執行 `$env:PORT = '4174'` 再啟動。變更網址、主機名稱或連接埠會使用不同的瀏覽器存檔空間，請先匯出進度。建議使用上述伺服器啟動，避免 `file://` 的存檔差異。

## 開始遊玩

1. 在「獵人」招募第二位夥伴，使用「自動編隊」或選擇前排位置。
2. 到「狩獵」按「開始狩獵」，觀察生命、魔力、掉落與戰報；可選 1×／2×／4×。
3. 從「任務」領取已達成獎勵，於「裝備」穿戴戰利品。
4. 回到城堡建造訓練場、鐵匠等設施；需要調整被占用的英雄時先召回隊伍。
5. 城堡面板的「公會生活」可前往流浪獵人、遠征、公會、神器、圖鑑與共鳴。其他系統隨王國進度解鎖。

## 操作

| 操作 | 方法 |
|---|---|
| 平移城堡 | 滑鼠拖曳／觸控單指拖曳 |
| 環繞檢視 | 按「環繞」，再拖曳調整角度 |
| 縮放 | 滾輪／雙指縮放／畫面上的 ＋、− |
| 查看防線 | 「全景」「俯視」「剖視」；設定中另有庭院預設 |
| 開啟設施 | 點擊建築或標牌，也可使用城堡設施清單 |
| 地圖與戰鬥 | 「世界地圖」拉遠看整圈十區；點地圖上任何一區的標籤就會把鏡頭飛過去並開始狩獵，全程留在同一張地圖 |
| 深淵入口 | 第 9 區「深淵裂谷」裡有一道實體裂隙之門，城堡內的深淵傳送門也還在 |
| 鍵盤介面 | Tab 移動焦點，Enter／空白鍵操作按鈕，Esc 關閉確認視窗 |
| 光照與聲音 | 設定中的日夜光照、日夜循環及各別音效／音樂音量 |

鏡頭與日照不影響遊戲亂數、戰鬥收益或日週重置。戰鬥倍率不縮短 20 秒休整與遠征的真實時間。

### 開放地圖

「王城」「世界地圖」「狩獵」三個視角**只是相機位置**，場景不會換：城堡、設施、十區地形、道路與深淵之門永遠都在同一張地圖上。

**這是一塊連在一起的大陸**，不是一堆浮空島。`WorldMap` 同時提供地形高度、群系、道路、障礙與尋路；`buildTerrain()` 依這份資料產生方塊。海岸基準半徑為 **504**（半徑是舊制的兩倍，面積四倍）。地形用三層 LOD 繪製：城堡周邊 ±175 用 2 格方塊、中距離 ±400 用 4 格、外圈再放大到 8 格。

**城堡的外圈是八邊形**（四邊 x ±92、z ±78，四角各切 42，台地與護城河都是同一個形狀往外推 6／16 格）。切角不是裝飾：zone 2 的競技場正好壓在城堡西南方的對角線上，方形外角一往外長就會撞進它的空地；切掉四角之後四邊都能推出去，對角線距離反而變大。改完之後**兩圈防禦的間距從 27／20／36 格變成 35／28／42 格，內牆到主堡也從 31.7／23.7 變成 42.8／30.8 格**，兩者都由 `node tools/world-audit.cjs` 與核心測試直接量測方塊幾何，不是只有常數好看。

十區依難度散布在離城堡約 **260–474** 的不規則方位，對應草原、幽暗森林、石峰、惡地、雪原、沙漠、沼澤、風蝕高地、深暗與蘑菇地。城門大道從 `(0,78)` 經過內外兩道城門與護城河橋，接到 `(0,236)` 的連續環路，進場路線經過實際可走的城門洞。

**派遣後隊伍會自己走過去打怪，而且走位與戰鬥是同一份資料。**隊伍與怪物的座標存在遊戲存檔裡（`hunting.field`），跟戰鬥數學用同一個 0.1 秒時鐘推進；畫面只負責把座標畫出來，不會自己算路線。因此「隊伍還沒到，血就開始掉」這種事不可能發生。

**隊伍有隊形。**成員不會疊在同一格上：每一步結束都會把座標推開到 2.6 格以上，只推合法的方向（不會被推進牆裡或水裡），所以行軍看起來是一列人而不是一團人。路線走完但怪物還在攻擊距離外時，成員會改以怪物當前位置為目標重新找路，不會站在集結線上發呆。

流程：城堡庭院 → 出城門 → 地圖道路 → 該區閘門 → 集結線 → 上前交戰。怪物在仇恨範圍（16 格）內會主動離開崗位衝出來迎擊，走到自己的攻擊距離就停；隊伍一進入攻擊距離就停下來打。換怪後隊伍若已走完舊路線，會重新尋路，不再永久停在攻擊距離外。戰敗只退到該區閘門，主動召回才會長途走回城堡。

**世界尋路**用 `WorldMap.findPath()` 的 8 方向 A*，每步檢查 `validStep()`；競技場內仍用 `GameData.zones[i].field.props` 和局部 A* 判定障礙。兩者與畫面共用座標。

**海岸線**由諧波與各區外凸控制，岸邊高度漸降；道路及護城河橋面保持可通行。

## 保存與離線

遊戲使用目前瀏覽器的本機儲存，每五秒及離開頁面時保存；成功操作後也會保存。「設定」提供立即保存、JSON 匯出與匯入。沒有雲端帳號同步，清除網站資料會刪除進度。

匯入會檢查格式、物件歸屬與數值，再要求確認替換。無效檔案不覆蓋現有進度。存檔格式版本為 `1`，地圖生成版本為 `2`；舊版地圖存檔保留資源與進度，但重建行走路線。不支援原版 MEGA IDLE／其他 Pixel World 存檔直接遷移。讀取舊資料失敗時會保留原文，可先使用「匯出原始備份」。

隊伍從城堡走到第 1～10 區大約要 14～30 秒（地圖放大後的實際秒數，行走速度 26 格／秒）。派遣中的主隊可結算最多 12 小時的估算離線收益；待命隊伍不領取主狩獵收益。離線不模擬推關、首通或擊殺數。回到頁面後只結算一次；訪客遠征與委託另依完成時間結算。

## 開發與驗證

```powershell
npm test
npm run test:browser
node tools/world-audit.cjs
node tools/content-audit.cjs
node tools/perf-probe.cjs --headed   # 效能：draw call／三角形／每幀 JS（--headed 才會用真 GPU）
```

`npm test` 執行核心與擴展規則測試。瀏覽器測試需要 Playwright 與 Chrome；目前設定位置見 `tests/browser.test.cjs`，其他電腦需調整可執行路徑。`tools/free-route.cjs` 是耗時較長的自動成長策略模擬，報告保存在 `docs/free-route.json`。

瀏覽器測試中有一條 `open world` 專門守住開放地圖的契約：十區同時存在、三個視角不改變場景方塊數、隊伍確實徒步走進該區、以及戰鬥就在同一張地圖上發生。

注意：headless Chromium 走軟體渲染（SwiftShader），每秒只跑得出少數幾個畫面，而角色步行是跟著動畫影格推進的；因此該測試用「等待狀態」而非「等待秒數」，在本機顯示卡上步行約四秒。

現有截圖見 `tests/shots/`。素材數量稽核、程式測試與長期策略模擬各自證明不同範圍，不能互相代替。
